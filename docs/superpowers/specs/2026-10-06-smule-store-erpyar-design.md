# Smule Store روی erpyar.ir

تاریخ: ۲۰۲۶-۱۰-۰۶

## هدف

اپ `smule_store` از مخزن `sepehrsariaslani/cookie` به‌عنوان وب‌سایت اصلی دامنهٔ `erpyar.ir` نصب و فعال شود، درحالی‌که پنل مدیریتی ERPNext بدون تغییر در مسیر `erpyar.ir/desk` باقی بماند.

## محدوده

### داخل محدوده

- نصب اپ Frappe با نام `smule_store` روی همان سایت ERPNext.
- استفاده از storefront موجود مخزن، شامل صفحات اصلی، منو، جزئیات محصول، ساخت کوکی، سبد خرید، checkout، حساب کاربری و پیگیری سفارش.
- فعال‌سازی مسیرهای عمومی storefront از جمله `/`, `/menu`, `/build-cookie`, `/cart`, `/checkout`, `/account` و صفحات پشتیبانی.
- نگه‌داشتن `/desk` به‌عنوان مسیر پنل ERPNext.
- اتصال سفارش‌ها به رکوردهای بومی ERPNext: `Item`, `Item Price`, `Customer`, `Sales Order`, `Payment Request` و `Payment Entry`.
- اجرای migration/install hookهای اپ برای ساخت فیلدهای سفارشی و تنظیم صفحهٔ اصلی.
- آماده‌سازی کاتالوگ نمونه برای بررسی UI، با علامت‌گذاری نمونه بودن داده‌ها.
- تست محلی routeها، APIها، migrationها و build storefront پیش از استقرار.

### خارج از محدودهٔ اولیه

- بازطراحی UI یا جایگزینی آن با ظاهر دیگری.
- فعال‌سازی پرداخت واقعی پیش از واردکردن تنظیمات معتبر زرین‌پال، حساب مالی، قیمت‌ها و اطلاعات شرکت.
- حدس‌زدن دستور غذا، آلرژن، قیمت یا سیاست ارسال واقعی فروشگاه.
- تغییر دادن کد هستهٔ Frappe یا ERPNext.
- استقرار مستقیم روی Frappe Cloud بدون مجوز یا دسترسی مدیریتی لازم.

## گزینه‌های بررسی‌شده

### گزینهٔ منتخب: اپ native در Frappe

اپ به‌صورت یک Frappe app نصب می‌شود و hookهای آن route صفحهٔ اصلی و APIهای storefront را مدیریت می‌کنند. این گزینه برای سفارش، حساب کاربری و پرداخت امن مناسب است و `/desk` را دست‌نخورده باقی می‌گذارد.

### گزینهٔ static-only

فقط فایل‌های HTML/CSS/JS روی صفحهٔ اصلی قرار می‌گیرند. این روش ظاهر را نشان می‌دهد اما سفارش، احراز هویت و پرداخت را به‌صورت قابل‌اعتماد به ERPNext وصل نمی‌کند.

### گزینهٔ سرویس مستقل با reverse proxy

فروشگاه به‌صورت سرویس جدا اجرا می‌شود و با reverse proxy در دامنه قرار می‌گیرد. این روش به همگام‌سازی نشست کاربر، API، مسیرها و deployment جداگانه نیاز دارد و برای این سایت پیچیدگی غیرضروری ایجاد می‌کند.

## طراحی نهایی

### مسیریابی

- `/` به `smule_storefront` هدایت می‌شود و storefront صفحهٔ اصلی خواهد بود.
- مسیرهای فروشگاه از hook موجود اپ استفاده می‌کنند.
- `/desk` خارج از routeهای storefront است و توسط ERPNext سرو می‌شود.
- صفحات login و signup موردنیاز حساب مشتری از سازوکار native Frappe استفاده می‌کنند.

### معماری داده

- دادهٔ اصلی کالا و قیمت در ERPNext باقی می‌ماند.
- فیلدهای سفارشی `smule_*` روی `Item` و اسناد مرتبط، metadata نمایشی و دستورهای فروشگاه را نگه می‌دارند.
- ثبت checkout پس از اعتبارسنجی، یک `Sales Order` و `Payment Request` بومی می‌سازد.
- پرداخت موفق فقط بعد از verify سمت سرور در زرین‌پال و تطبیق مبلغ ثبت‌شده، `Payment Entry` ایجاد می‌کند.
- سفارش مهمان با token پیگیری محدود و سفارش کاربر واردشده با حساب Customer به سفارش متصل می‌شود.

### راه‌اندازی داده

- ابتدا migration و install hook اجرا می‌شود.
- کاتالوگ نمونه فقط برای نمایش و آزمون قابل seed است و با وضعیت sample علامت‌گذاری می‌شود.
- قبل از فعال‌سازی checkout واقعی، کالاهای تاییدشده، `Item Price` با واحد مناسب، شرکت و ارز `IRR`، حساب دریافت وجه، روش پرداخت، آدرس و ساعات pickup باید در ERPNext تنظیم شوند.
- تنظیمات زرین‌پال در فیلد رمزنگاری‌شدهٔ تنظیمات اپ ذخیره می‌شود و callback فقط روی HTTPS عمومی فعال خواهد شد.

### خطا و ایمنی

- دادهٔ نمونه یا کالای بدون قیمت مجاز به سفارش واقعی نیست.
- callback ناموفق، مبهم، تکراری یا با مبلغ ناهماهنگ به‌عنوان پرداخت موفق ثبت نمی‌شود.
- retry پرداخت فقط برای سفارش‌های مجاز و از مسیر کنترل‌شده انجام می‌شود.
- خطاهای پیکربندی به کاربر پیام قابل‌فهم می‌دهند و اطلاعات حساس در پاسخ عمومی نمایش داده نمی‌شود.
- قبل از اعمال migration روی سایت زنده، backup و بررسی وضعیت سایت انجام می‌شود.

## برنامهٔ اعتبارسنجی

1. بررسی ساختار و lint کد Python و TypeScript/JavaScript.
2. اجرای unit testهای domain و API اپ.
3. اجرای build/export storefront و اطمینان از وجود assetهای موردنیاز.
4. نصب اپ روی سایت آزمایشی یا محیط محلی Frappe و اجرای migrate/clear-cache.
5. بررسی HTTP مسیرهای `/`, `/menu`, `/cart`, `/checkout` و `/desk`.
6. بررسی اینکه `/desk` به پنل ERPNext می‌رسد و route اصلی به storefront.
7. آزمون checkout بدون فعال‌سازی پرداخت واقعی و آزمون callbackهای شکست/تکرار با دادهٔ آزمایشی.
8. پس از تأیید، استقرار روی Frappe Cloud، پاک‌سازی cache و بررسی smoke test روی `erpyar.ir`.

## پیش‌نیاز استقرار

- دسترسی مدیریتی یا مسیر رسمی نصب custom app در Frappe Cloud برای سایت `erpyar.ir`.
- امکان نصب اپ از مخزن GitHub و دسترسی سایت به نسخهٔ ERPNext موردنیاز.
- backup قابل‌بازگشت پیش از migration.
- تنظیمات واقعی شرکت، قیمت‌ها، pickup/delivery و در صورت نیاز credentials زرین‌پال.

- `https://erpyar.ir/desk` همچنان پنل ERPNext را نمایش دهد.
- کاتالوگ و داده‌های ERPNext از مسیرهای storefront خوانده شوند.
- تا پیش از تکمیل تنظیمات مالی، پرداخت واقعی ناخواسته فعال نشود.
- تست‌های اپ و build storefront بدون خطای جدید اجرا شوند.
